# Step 2.7 Implementation Plan — The Window Is the Server

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bokkie serves only while a person has its window open, controlled from
a screen rather than a console, and an upgrade removes the service that used to
start it on its own.

**Architecture:** The exe starts the server, opens the app in a dedicated
browser window, and waits on that browser process; when it exits, the server
drains and stops. The control screens are Vue pages in the SPA already shipped,
behind a host-only API — the same `isHostRequest` gate the LAN switch uses, so
nobody on the station network can press Stop.

**Tech Stack:** Go 1.27, `CGO_ENABLED=0`, Vue 3 + Vite (already present),
`golang.org/x/sys/windows`. No GUI toolkit and no new module.

**Spec:** [02.7-window-is-the-server.md](02.7-window-is-the-server.md) — read it
first, including the five consequences. This plan argues from its D1–D9.

## Global Constraints

- `CGO_ENABLED=0`. **No GUI toolkit**, no cgo, no new module dependency.
- **D1 is a hard requirement.** Nothing may install a service, a `Run`/`RunOnce`
  key, a Startup-folder shortcut, a scheduled task, or a recovery restart. Task 3
  asserts all five.
- **The control API is host-only.** Reuse `isHostRequest` from
  `internal/api/network.go`. A Stop button reachable from the LAN is a station
  anybody can switch off.
- `internal/service` is **not deleted** (D7). It stays for macOS and Linux and as
  the way back to unattended operation.
- The database is the whole product. No task may make an existing ledger
  unreachable; Task 4 is written around that one sentence.
- Copy is read by counter staff. Match the voice already in `winsetup/console.go`.
- Service name `bokkie`, default port `8080`, LAN name `<mdns.hostname>.local`.

## Review Focus

1. **A browser already running** makes `--app` return instantly, so waiting on it would stop the server a second after it started — Task 2.
2. **A Stop request from the LAN** must be refused; the control API is host-only — Task 6.
3. **An upgrade where the admin prompt is declined** must say plainly that the old service is still installed and will still start on its own — Task 3.
4. **Both data folders holding a database** must resolve to the one with real data, never silently to the empty one — Task 4.
5. **Closing the window during a backup** must not leave a file that fails its own verification — Task 5.

## Task 1: `serve` — the foreground lifecycle

**Files:**
- Create: `cmd/bokkie/serve.go`, `cmd/bokkie/serve_test.go`
- Modify: `cmd/bokkie/main.go` (add `serve` to the switch and `usage`)

**Interfaces:**
- Consumes: `app.New`, `bootstrap`, `app.(*App).Start/Stop`.
- Produces: `cmdServe(args []string) error`; `serveUntil(ctx context.Context, log *slog.Logger, server *app.App, stop <-chan struct{}) error`.

- [ ] **Step 1: The lifecycle, separated from what triggers it**

`serveUntil` runs the server until `stop` closes or the context is cancelled.
Taking the stop signal as a channel is what makes the next task's "the browser
exited" and this task's "Ctrl+C" the same code, and makes both testable:

```go
// serveUntil serves until something says to stop, then shuts down cleanly.
//
// The reason to stop arrives as a channel rather than being discovered here:
// Ctrl+C, a closed console, and the window being closed are three different
// events that must all end in the same drain, and a function that knew about
// any one of them could not be tested without producing it.
func serveUntil(ctx context.Context, log *slog.Logger, server *app.App, stop <-chan struct{}) error {
	if err := server.Start(); err != nil {
		return err
	}

	signals := make(chan os.Signal, 1)
	signal.Notify(signals, os.Interrupt, syscall.SIGTERM)
	defer signal.Stop(signals)

	select {
	case <-stop:
		log.Info("the window was closed; stopping")
	case sig := <-signals:
		log.Info("stopping", "signal", sig)
	case <-ctx.Done():
	}

	shutdown, cancel := context.WithTimeout(context.Background(), shutdownWait)
	defer cancel()
	return server.Stop(shutdown)
}

// shutdownWait bounds the drain. It is longer than a request and far shorter
// than a person's patience with a window that will not close.
const shutdownWait = 10 * time.Second
```

- [ ] **Step 1: The arguments, and the one that makes this work at all**

`internal/winsetup/window.go`:

```go
// WindowArgs opens a browser in application mode — no address bar, no tabs — on
// its own profile directory.
//
// --user-data-dir is the load-bearing one, and it is not about the profile. A
// browser that is already running treats a second launch as "open a window in
// the existing process" and the new process exits immediately. Waiting on that
// process would then stop the station about a second after it started, on every
// machine where somebody had a browser open — which is every machine. Its own
// profile directory forces its own process, which is a thing that can be waited
// on.
func WindowArgs(address, profileDir string) []string {
	return []string{
		"--app=" + address,
		"--user-data-dir=" + profileDir,
		// Nothing in this window should offer to become a normal browser.
		"--no-first-run",
		"--no-default-browser-check",
		"--disable-extensions",
	}
}
```

```go
// windowClosed closes when the browser window the station was opened in exits.
func windowClosed(log *slog.Logger, address string) (<-chan struct{}, error) {
	profile, err := os.MkdirTemp("", "bokkie-window-")
	if err != nil {
		return nil, err
	}

	process, err := winsetup.OpenWindow(address, profile)
	if err != nil {
		// No browser is not a reason to refuse to serve. The console stays the
		// switch, and the person is told which window to close.
		log.Warn("could not open a window; this console is the station's switch now",
			"close_this_to_stop", true, "error", err)
		return make(chan struct{}), nil
	}

	stop := make(chan struct{})
	go func() {
		process.Wait()
		os.RemoveAll(profile)
		close(stop)
	}()
	return stop, nil
}
```

## Task 4: The data folder moves, and brings the ledger with it

**Files:**
- Create: `internal/config/adopt.go`, `internal/config/adopt_test.go`
- Modify: `internal/config/datadir_windows.go`

**Interfaces:**
- Produces: `config.ChooseDataDir(candidates []Candidate) (string, error)`; `config.Candidate{Path string, HasDatabase bool}`.

- [ ] **Step 1: The choice, as a pure function**

This is the one task where a mistake loses a year of lending records, so the
decision is a function with no filesystem in it:

```go
// Candidate is a data folder that might be the one holding the ledger.
type Candidate struct {
	Path        string
	HasDatabase bool
}

// ChooseDataDir picks the folder to use.
//
// The rule is "follow the data". The preferred location is first in the list,
// but a folder with a database in it beats an empty preferred one every time:
// a newer exe that silently opens an empty ledger on a station with real money
// in it is the worst outcome this system has, and it must not be reachable by
// double-clicking.
//
// Two folders with databases is not a choice to make quietly. It is refused,
// named, and left to a person.
func ChooseDataDir(candidates []Candidate) (string, error) {
	var withData []Candidate
	for _, c := range candidates {
		if c.HasDatabase {
			withData = append(withData, c)
		}
	}

	switch len(withData) {
	case 0:
		if len(candidates) == 0 {
			return "", errors.New("no data folder to choose from")
		}
		return candidates[0].Path, nil
	case 1:
		return withData[0].Path, nil
	default:
		return "", fmt.Errorf(
			"two folders on this computer hold a Bokkie database, and picking one of them "+
				"automatically could hide a year of records:\n  %s\n  %s\n"+
				"Move or rename the one that is not in use, then start Bokkie again",
			withData[0].Path, withData[1].Path)
	}
}
```

## Task 5: Backups get a pulse

**Files:**

**Interfaces:**

- [ ] **Step 1: A backup at both ends of the session**

Consequence 3 of the spec: a station closed at night never reaches its nightly
job. `Start` takes one after the server is up, `Stop` takes one before the
database closes, and both are logged.

The shutdown one runs **inside** the drain, before `database.Close()`, and is
skipped if one is already running — Review Focus 5: a `VACUUM INTO` interrupted
part-way leaves a file that fails its own verification, which is worse than no
file because somebody will trust it.

## Task 6: The control API, host-only

**Files:**
- Create: `internal/api/control.go`, `internal/api/control_test.go`
- Modify: `internal/api/api.go` (route registration)

**Interfaces:**
- Consumes: `isHostRequest`, `refuseNonHost`, `diagnose.Run`, `app.(*App).LastBackup`.
- Produces: `GET /api/control/status`, `POST /api/control/stop`, `GET /api/control/check`, `PUT /api/control/name`.

- [ ] **Step 1: The gate comes first**

Every control route is wrapped host-only, regardless of the LAN access setting.
The LAN switch decides who may *use* the app; this decides who may switch the
station off, and those are not the same question:

```go
// withHostOnly refuses a request that did not come from this machine, whatever
// the LAN access setting says.
//
// The network gate answers "may the counter PCs work today". This answers "may
// that machine switch the station off", and the answer is no even on a day when
// the first is yes. A Stop button reachable from the station network is a
// station anybody can close.
func withHostOnly(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		if !isHostRequest(r) {
			refuseNonHost(w, r)
			return
		}
		next.ServeHTTP(w, r)
	})
}
```

- [ ] **Step 3: The four handlers**

`status` is written out here because Task 7 consumes its field names verbatim,
and a disagreement between the two is a blank screen rather than a compile
error:

```go
type statusBody struct {
	Serving bool `json:"serving"`
	// Address is this machine's own, which always works. LANAddress is the
	// name the counter PCs use, which is the one that can be wrong — they are
	// reported separately so the screen can offer the second without implying
	// the first depends on it.
	Address    string `json:"address"`
	LANAddress string `json:"lanAddress"`
	Version    string `json:"version"`
	// LastBackup is RFC3339, or null when there has never been one. Null
	// rather than a zero time: "none yet" and "1 January year 1" read very
	// differently to somebody checking whether their records are safe.
	LastBackup *string `json:"lastBackup"`
	Name       string  `json:"name"`
}

func (d Deps) handleStatus(w http.ResponseWriter, r *http.Request) {
	at, _ := d.App.LastBackup()
	var last *string
	if !at.IsZero() {
		formatted := at.Format(time.RFC3339)
		last = &formatted
	}
	writeJSON(w, http.StatusOK, statusBody{
		Serving:    true, // it answered, which is the only proof that counts
		Address:    fmt.Sprintf("http://localhost:%d", d.Port),
		LANAddress: fmt.Sprintf("http://%s.local:%d", d.Hostname, d.Port),
		Version:    buildinfo.Version,
		LastBackup: last,
		Name:       d.Hostname,
	})
}
```

The other three:
`check` runs `diagnose.Run` and returns its `Report` as JSON — the same checks
and the same words the console prints, so there is one set of them.
`stop` returns 202 and then closes the stop channel, so the response is written
before the server begins draining.
`name` validates a hostname (letters, digits, hyphen; no dots) and writes
`mdns.hostname` to the settings file, then re-advertises.

## The gate

On the real Windows 10 machine:

1. The exe is opened; a window appears and the app works from a counter PC.
2. The window is closed; the counter PC loses it within seconds, and the port is
   free.
3. **The machine is restarted and nobody opens the window. Nothing is serving.**
   This is the hard requirement, and it is the one that must be seen rather than
   reasoned about.
4. The old service from v0.0.2 is gone, and Add/Remove Programs no longer lists
   Bokkie.
5. The ledger from before the upgrade is still there, with its advances and
   payments.
6. A contested name is reported, a new one is typed, and the counter PC reaches
   the station at it.
7. Closing the window leaves a backup that verifies.
